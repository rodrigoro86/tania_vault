# Tools (plataforma + ClickUp) Implementation Plan

> **For agentic workers:** execução: o **Strata** implementa cada tarefa (prompt em `.strata/tasks/TOOLS-Tn-*.md`, gerado
> desta seção); o **Claude Code** revisa o diff, roda os testes, corrige e faz o commit. Steps em checkbox (`- [ ]`).

**Goal:** funcionalidades viram tools (serviços HTTP com manifesto + MCP + páginas em iframe), e o ClickUp é a primeira.

**Architecture:** o backend Rust guarda o registro (env + tabela `tools`), faz proxy de `/tools/{id}/ui|api/*` com os headers
da Tania e serve `/api/core/config` às tools. O agente (Node, até a F5) junta as funções MCP das tools às suas. O front
monta faixa de ícones, rotas e Propriedades a partir dos manifestos. O ClickUp sai do núcleo para `app/tools/clickup/`.

**Tech Stack:** Rust (axum 0.8, sqlx 0.8, reqwest), Node 24 (TS por type stripping, `node:test`), React + Vite.

**Spec:** `docs/superpowers/specs/2026-11-06-tools-design.md`

## Global Constraints

- Sem dependência nova (Cargo.toml e package.json só mudam se o plano disser).
- Id de tool, de página e de vínculo: `^[a-z0-9-]{1,32}$`. URL: `http://` ou `https://`, até 300 chars.
- Headers: `x-tania-tool-secret`, `x-tania-user`, `x-tania-admin` (`1`/`0`). Tool → núcleo: `Authorization: Tool <id>:<segredo>`.
- Env: `TANIA_TOOLS=id=url,id2=url2`; segredo em `TANIA_TOOL_SECRET_<ID>` (maiúsculas, `-` → `_`); na tool: `TANIA_TOOL_SECRET`, `TANIA_CORE_URL`.
- Erros JSON `{ok:false, error}` em português, como o resto da API.
- Segredos nunca voltam para o front nem para os logs; comparação de segredo em tempo constante (`subtle`).
- Rust: `cargo fmt`, `cargo clippy --all-targets -- -D warnings`, `TEST_DATABASE_URL=postgres://postgres:test@127.0.0.1:5433/tania_test cargo test`.
- Node: testes rodam com Node 24 (`docker run --rm -v "$PWD":/app -w /app node:24-alpine node --test server/tests/*.test.mjs tools/*/tests/*.test.mjs`).

## Review Focus

1. Tool fora do ar ou lenta: `GET /api/tools` responde em ≤ 3 s com `erro` nela, o agente segue sem as funções dela (T1, T4).
2. Cliente forjando `x-tania-tool-secret`/`x-tania-user` no proxy: o valor forjado nunca chega à tool (T3).
3. Caminho com `..` ou `%2e%2e` em `/tools/{id}/ui/...`: não escapa do prefixo `ui/`/`api/` na tool (T3).
4. Manifesto com `id` diferente do registrado ou malformado: tool aparece com `erro`, sem ícone, sem quebrar as outras (T1, T6).
5. Nome de função MCP com caractere fora de `[a-zA-Z0-9_-]` ou longo: sanitizado e ainda chamável; colisão entre tools não sobrescreve (T4).
